## Overall assessment

The fork's core work — Silero v6 driven correctly, the speech clock,
the readiness-based recording start, the coordinator state machine, the
extra-engine lease/unload bookkeeping — is careful and matches its own
documentation where it matters. The defects clustered in three places:

1. **`MultiSttAction` is a ~900-line copy of `TranscribeAction` that drifted**
   behind it (readiness, cancellation, WAV verification, direct-stream
   awareness). Four of those are closed here; the remaining structural fix is
   to extract the shared stages so the two cannot diverge again.
2. **The performance-mode design leaked into shortcut registration** in a way
   that silently disabled hotkeys and removed users' bindings. Registration is
   now consistent and only constrained while performance mode is on; whether
   fresh installs should ship with empty hotkeys is the maintainer's call.
3. **Two type-boundary regressions** — the `u64 → u32` narrowing and the
   accent colour with no persistence path — were invisible to every static
   check because both sides compiled. The `settingUpdaters` map and the
   `#[specta(type = f64)]` pattern are now documented in AGENTS.md so the next
   setting/field doesn't repeat them.

## Method

- Five independent reviewers over disjoint file sets, each instructed to
  quote `file:line` evidence and to say when unsure. Every finding acted on
  was re-read in the source by the coordinating reviewer first; two claims
  were rejected (`display()` vs `full`, "identical blocks" in the Windows
  permission ladder) and one downgraded (H1 → deliberate design, partially
  fixed).
- No behaviour was changed without a compile + test run: `cargo check`,
  `cargo clippy`, `cargo test` (261 + 1), `tsc`, oxlint, prettier and
  `check-translations` all ran after the edits.
- `bindings.ts` was hand-edited to match the Rust changes (one command added,
  one settings field removed); the next `bun run tauri dev` regenerates it and
  should produce no diff.

## Second pass (same day): direct streaming rule and remaining items

After the checkpoint above, the direct-streaming double paste (#10) was closed
by a scoping rule rather than a replacement mechanism: direct streaming types
into the app **only for plain transcription**. When the result will be
post-processed or merged (Multi-STT), `TranscriptionManager::start_stream(false)`
keeps the writer from being created, `effective_overlay_style` forces the Live
overlay (if the model streams) so the transcript is still previewed, and the
processed result is pasted once through `clipboard::paste_with_method(…,
Some(PasteMethod::CtrlV))`. An earlier select-verify-replace design for the
same problem was prototyped and then removed in full as over-engineered; no
trace of it remains in the tree. The same pass closed #9, #35, #36 and #37
(statuses updated in the tables).

Verification after the second pass: `cargo check` / `fmt` clean; clippy at
the 67-warning upstream baseline; **264** + 1 tests pass (3 new for the direct
streaming rule); `tsc`, oxlint and prettier clean; `check:translations`
reports 87 missing keys per locale (86 + the new shortcut-validation string).
